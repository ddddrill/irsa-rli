## Что это такое

**IRSA** — симулятор радара с инверсной синтезированной апертурой (ISAR): он синтезирует эхо-сигнал SFCW-радара от вращающейся цели и проводит его через полный конвейер обработки — до готового радиолокационного изображения (РЛИ) космического аппарата.

- **Полный цикл в одном окне:** сырые I/Q-отсчёты → профили дальности → MOCOMP → фокусировка → РЛИ; каждый этап виден на отдельной вкладке GUI.
- **5 реальных миссий** в роли целей: CloudSat, CALIPSO, ICESat-2, LRO, Hinode (Solar-B) — упрощённые модели точечных рассеивателей.
- **Два пути фокусировки:** Range-Doppler для малых углов и полярное переформатирование для больших — с автоматическим выбором по физическому порогу √(λ/L)/2.
- **Детерминированность:** все случайные эффекты (шум, анизотропия, фазовый шум) — из seeded RNG; один seed — побитово одинаковый результат при любом SNR.

Кому нужно: студентам и аспирантам (тренажёр Range-Doppler / MOCOMP / полярного переформатирования), исследователям (песочница до выхода на реальный радар), преподавателям (11 демо с PNG-выходом), инженерам (модульный референс на Python).

**Вопросы-эксперименты** — каждый проверяется за минуту:

- «Что будет, если уменьшить полосу в 2 раза?» — разрешение по дальности $\Delta r = c/(2B)$ упадёт вдвое.
- «Как MOCOMP справляется с поступательным движением ≈ 7.5 км/с?» — Range Walk и фазовая развёртка убираются (демо 3).
- «Что произойдёт, если спутник повернётся на 15°?» — в стандартном конвейере arc smearing; полярное переформатирование возвращает точки в фокус.
- «Какой суммарный угол Δθ допустим для моих параметров?» — физический порог Δθ < √(λ/L)/2 (врезка в разделе «Физика»).

## Физика: как радар «видит» спутник

### Что такое ISAR

Обычный радар измеряет **дальность** до объекта — расстояние по лучу. Этого мало: непонятно, **где** в поперечном направлении (по азимуту) находится отражатель.

**ISAR (Inverse Synthetic Aperture Radar)** решает эту задачу за счёт **вращения цели**. Если объект поворачивается относительно радара, разные его точки имеют разную лучевую скорость → разный доплеровский сдвиг → их разделяет БПФ по частоте.

> Представьте вертушку: лопасти вращаются, кончик каждой лопасти движется быстрее основания. Радар «видит» это как разные доплеровские частоты. Точка на расстоянии $x$ от оси вращения даёт $f_d = \frac{2\omega x}{\lambda}$ — линейка этих частот и есть азимут (cross-range).

Числа по умолчанию для X-диапазона:

| Величина | Формула | Значение |
|---|---|---|
| Длина волны | λ = c / f_c | 3.75 см (8 ГГц) |
| Разрешение по дальности | Δr = c / (2B) | 0.30 м (B = 0.5 ГГц) |
| Разрешение по азимуту | Δx = λ / (2·Δθ) | ≈ 0.36 м (при Δθ = 3°) |
| Доплер точки на x = 10 м | f_d = 2·ω·x / λ | ≈ ±280 Гц (при ω = 0.52 рад/с) |
| Суммарный угол поворота | Δθ = ω·N·PRI | 15° (N = 1000, PRI = 0.5 мс, ω = 0.524 рад/с) |

### Сигнал SFCW

В проекте используется **SFCW (Stepped Frequency Continuous Wave)** — радар, который излучает импульсы на последовательно меняющихся частотах:

```
Частота:   f₀,  f₀+Δf, f₀+2Δf, ..., f₀+(M-1)·Δf
Импульс:   n=0,  n=1,  n=2,    ..., n=N-1
```

Каждый отсчёт — комплексное число (I/Q), пропорциональное напряжённости поля, отражённого целью. На выходе — матрица E[M×N] (частоты × импульсы).

### Дальность и азимут

- **Дальность (Range)** восстанавливается по быстрому времени (внутри импульса) через IFFT по оси частот. Разрешение: $\Delta r = c / (2B)$.
- **Азимут (Cross-Range)** восстанавливается по медленному времени (между импульсами) через FFT по оси доплеровских частот. Разрешение: $\Delta x = \lambda / (2\omega T_{\text{obs}})$.

### Почему нужно учитывать движение

Спутник не просто вращается — он движется по орбите со скоростью ≈ 7.5 км/с. Поступательное движение приводит к:

- **Range Walk** — каждая точка «ползёт» по бинам дальности от импульса к импульсу (косые линии на профилях).
- **Фазовому набегу** — линейный фазовый тренд по медленному времени, размывающий азимутальное FFT.

Без компенсации РЛИ теряет фокус. **MOCOMP** (Motion Compensation) — обязательный шаг перед азимутальным сжатием.

### Проблема больших углов и полярное переформатирование

При малых углах обзора данные в **k-пространстве** (пространстве волновых чисел) лежат почти на прямоугольной сетке, и 2D БПФ работает корректно. При больших углах (типично для ISAR X-диапазона на длинных экспозициях) сетка становится **кольцевым сектором** — и 2D БПФ даёт **arc smearing** (размазню в виде дуг).

Решение — **полярное переформатирование**: пересчёт данных с полярной сетки на декартову перед 2D IFFT.

> **Порог включения полярного пути.** В коде (`should_use_polar_reformat`) порог — физический критерий применимости узкоугольной полярной аппроксимации: $\Delta\theta_{\max} \approx \sqrt{\lambda/L}/2$ (C. Chen, M. Martorella, *Inverse Synthetic Aperture Radar Imaging*, IET, 2014, §3.1). Для X-диапазона и цели размером L = 20 м это ≈ 1.2°. Если длина волны или размер цели неизвестны, код использует запасной эмпирический порог **3°**. Практически: при Δθ ниже порога искажения стандартного конвейера малозаметны, выше — включается полярный путь.

## Конвейер

```mermaid
flowchart LR
    A["SFCW-генерация<br>E[M×N]"] --> B["Сжатие по дальности<br>1D IFFT"]
    B --> M["MOCOMP<br>выравнивание + фазовый автофокус"]
    M --> D{"Δθ < √(λ/L)/2 ?"}
    D -- "да" --> E["Азимутальное сжатие<br>1D FFT"]
    D -- "нет" --> F["Полярное переформатирование<br>(k,θ)→(kx,ky), 2D IFFT"]
    E --> G["РЛИ |I|, оси в метрах"]
    F --> G
```

| Этап | Модуль | Что делает |
|------|--------|------------|
| Генерация | `simulation/raw_generator.py` | E[m,n] = Σ σᵢ · exp(−j4πfₘRᵢ(tₙ)/c) |
| Сжатие по дальности | `processing/range_compress.py` | 1D IFFT по частотам + дешифровка |
| MOCOMP | `processing/mocomp.py` | Выравнивание огибающей (суббиновое) + фазовый автофокус |
| Сжатие по азимуту (стандарт) | `processing/azimuth_compress.py` | 1D FFT по импульсам |
| Полярное переформатирование | `processing/polar_reformat.py` | (k,θ) → (kx,ky), билин. интерполяция, окно, 2D IFFT |
| Keystone (опция) | `processing/keystone.py` | Устранение остаточной миграции по дальности |
| TF-анализ / RID (опция) | `processing/tf_analysis.py` | STFT-спектрограммы, WVD, RID-кадры |
| Кросс-масштаб (опция) | `processing/cross_range_scaling.py` | Оценка ω по данным (phasefit) → физическая ось |

## Возможности

**Моделирование**

- 5 миссий-целей: CloudSat, CALIPSO, ICESat-2, LRO, Hinode — модели рассеивателей (.pkl) с паспортами и изображениями.
- SFCW-радар с параметризуемой несущей, полосой, числом частот, шириной ДН.
- Кинематика: поступательное движение (V, α), вращение (ω), угловое ускорение (γ) и микровибрация (микро-Доплер).

**Эффекты реализма** *(v2.4.0; все выключены по умолчанию, пресеты «Идеальный / Реалистичный»)*

- комплексные амплитуды рассеивателей σᵢ·e^(jφᵢ) и анизотропия ЭПР по углу;
- геометрическое затенение (occlusion) и двухпутевая ДН антенны с ошибкой наведения;
- фазовый шум гетеродина (винеровский процесс) и аддитивный шум с заданным SNR.

**Обработка**

- сжатие по дальности (1D IFFT) и по азимуту (1D FFT);
- окна: none / hamming / hann / kaiser / chebwin / taylor + взвешивание по дальности;
- MOCOMP v2: суббиновое выравнивание огибающей (усреднённая опора) + фазовый автофокус;
- полярное переформатирование для больших Δθ: k-space, билинейная интерполяция, окно Тейлора, 2D IFFT; автоматический выбор конвейера по физическому порогу √(λ/L)/2;
- keystone (опция) — устранение остаточной миграции по дальности;
- кросс-range масштабирование по данным (метод phasefit) вместо осевой ω из конфигурации;
- время-частотный анализ: STFT-спектрограммы, WVD, RID-кадры — маневрирующая цель (γ ≠ 0);
- метрики фокусировки: энтропия изображения, ISNR; отображение linear/dB.

**Инструментарий**

- GUI на PyQt5 + pyqtgraph: 6 вкладок = 6 стадий конвейера, tooltips с формулами;
- 12 скриптов в `examples/` (11 демо + интеграционный тест) с автосохранением PNG;
- pytest-набор (14 файлов, 78 тестов): обратная совместимость, детерминизм по seed, юнит-тесты эффектов и новых модулей, интеграционный прогон конвейера;
- seeded RNG: одинаковый seed → побитово одинаковый результат (проверяется тестом).

|---|---|
| Лучше разрешение по дальности | ↑ B, ↑ nifft_size |
| Лучше разрешение по азимуту | ↑ Δθ (больше суммарный угол поворота) |
| Меньше боковых лепестков | window = hamming / hann |
| Чётко при больших Δθ | полярное переформатирование |
| Подавить поступательное движение | MOCOMP |
| Снять задержку апертуры при γ ≠ 0 | TF-конвейер (вкладка «Сигнатуры») |

## Тесты и воспроизводимость

```bash
python -m pytest -q          # обратная совместимость, детерминизм, эффекты, интеграция, юнит-тесты модулей, геометрическая истинность
python -m examples.test_data_processor_polar   # интеграционный прогон с метриками и [OK]-проверками
```

Что проверяется автоматически:

- **обратная совместимость** — с выключенными эффектами генератор воспроизводит классическую формулу точечных рассеивателей;
- **детерминизм** — один seed даёт побитово одинаковые данные (центральный seeded RNG, `simulation/rng.py`); обещание верно **при любом SNR**, включая конечный (шум AWGN берётся из подгенератора `spawn_rng(seed, "awgn")` — фикс G2, ранее шум шёл из глобального `np.random` и воспроизводимость при SNR < ∞ нарушалась);
- **корректность эффектов реализма** — юнит-тесты амплитуд, затенения, фазового шума;
- **новые модули R2–R8** — юнит-тесты keystone, кросс-масштабирования, TF-анализа, суббинового MOCOMP, физического порога;
- **сквозной конвейер** — стандартный и полярный пути выдают сфокусированные РЛИ с физическими осями.

## Ограничения и планы

Проект фиксирует границы применимости текущей версии:

- **Автофокус** реализован одним методом — по опорному рассеивателю (PPP). PGA и контрастные методы (ICBA) не реализованы: при отсутствии доминирующего отражателя качество фокусировки падает.
- **Кросс-range масштабирование по данным** работает, когда оценка угловой скорости сходится (phasefit, ≥ 3 опорных точек); иначе ось азимута строится по ω из конфигурации.
- **WVD** билинеен по природе: для многоточечной цели даёт кросс-термы; для сложных сцен используйте STFT-спектрограмму или RID.
- **Keystone** — опция, выключенная по умолчанию; применимость ограничена сходимостью оценки и условиями узкой полосы. При γ ≠ 0 «слепой» PFA-конвейер расфокусируется — корректный фокус даёт TF-конвейер (RID).
- **Модели целей** — упрощённые точечные рассеиватели, вдохновлённые геометрией реальных миссий, а не официальные ЭПР-модели.

Дорожная карта изменений — в [CHANGELOG.md](CHANGELOG.md).
